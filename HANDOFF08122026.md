## 1. Project context — what this is, the stack, how to run it

**eNoVo** (internally "Sangam PWA", formerly ethniCity/EthniZity) is a Progressive Web App for diaspora/ethnic communities: social feed, people discovery, business directory, housing, events, travel companions, forums, **end-to-end-encrypted messaging**, WebRTC 1:1 + group audio/video calls, and a large **catering module** (direct orders + RFP/quotes + vendor dashboard + storefront builder). It ships as a web PWA and an **Android app via Capacitor**.

**Tech stack**
- React 19.2 + TypeScript (strict), Vite 7.3 + PWA plugin (vite-plugin-pwa)
- Tailwind CSS v4 (`@custom-variant dark (&:where(.dark, .dark *))` — `:where()` has zero specificity)
- Firebase: Firestore (primary DB), Auth, Storage, Hosting, Cloud Functions (2nd-gen / Cloud Run), FCM
- Capacitor Android wrapper; Framer Motion; Lucide icons
- Messaging crypto: Web Crypto API (ECDH P-256 + AES-256-GCM) + legacy CryptoJS v1; WebRTC uses DTLS-SRTP + a paid Metered TURN server
- i18next, react-router-dom v7, recharts, zod

**Firebase project / hosting:** project + site **`mithr-1e5f4`**. Live at `https://mithr-1e5f4.web.app` + custom domains `enovoapp.com`, `ethnizity.com`, `enovoapp.online`, `enovoapp.org`, `enovoapp.store`.

**Local path (Mac):** `/Users/sarathsatheesan/ethniCity_03_19_2026/sangam-pwa-v2`
**GitHub:** `https://github.com/sarathsatheesan/sangam-pwa-v2` (branch `main`). Auth is via a fine-grained PAT `sangam-push-2` stored in the **macOS Keychain** (credential.helper osxkeychain) — the remote URL is clean (no embedded token). Pushes authenticate silently.

**Commands (all run on the Mac — see §5 for why builds/deploys are Mac-only):**
```bash
npm run dev        # Vite dev server
npm run build      # tsc -b && vite build
npm test           # vitest run — 270 tests, gates deploys
npm run lint       # eslint
npm run ship       # test → build → cap sync android → firebase deploy --only hosting  (web + Android assets)
npm run android:check   # verify Android assets match dist before device testing
firebase deploy --only firestore:rules        # rules only (instant, reversible)
firebase deploy --only functions,firestore:indexes   # functions/indexes (NOT covered by ship)
```
After `npm run ship`, you must also open **Android Studio → Run ▶** to install on the physical tablet (Capacitor can't push to a device headlessly).

## 4. Decisions & rationale (do not relitigate)

- **messages I/O extraction = mechanical moves only.** `services/messages.ts` follows the `services/feed.ts` conventions: identical queries/payloads, page keeps its try/catch + toasts, `subscribeX()` returns the unsubscribe. The `msgSnapshotSeqRef` race guard is passed INTO `subscribeToThreadMessages` as the page's long-lived `{current}` ref so a stale async handler still sees bumps from its replacement. Group-ness is computed at effect-creation to preserve the exact prior stale-closure semantics.
- **Security fixes were risk-ordered and each rule was verified against real client-write paths BEFORE locking.** This deliberately avoided breaking legit flows: `moderationQueue` stays open (normal users file reports); `businesses` update stays broadly allowed but only the `verified`/`verificationMethod` trust-fields are locked to admin (reviews/reports write the doc); `notifications` create stays open with a tracked-risk note (the whole app enqueues them) — only READ was tightened; `appConfig` locked to `isAdminUser()` not `false` (the admin panel manages it).
- **The E2EE redesign was deliberately STAGED, not shipped.** C1 and C2 are coupled (true E2EE needs secure multi-device key sync, which C1 removes), touch the repo's highest-risk file, and a botched migration could strand all message history. Better to spec it (report §7) and do it deliberately.
- **Legal docs:** two structures (mutual + one-way) × two types (NDA + non-compete) = 4 docs, per the user's "both, two docs each." Cross-border US↔India ⇒ a neutral-seat arbitration clause and an explicit **India §27 Contract Act** caveat (post-termination non-competes are generally void in India → lean on confidentiality + non-solicit). Templates only, not legal advice.
- **GitHub token** kept in macOS Keychain (not embedded in `.git/config`) — decided during the security review to keep secrets out of plaintext. Token `sangam-push-2` has **No expiration** (user's explicit choice).

## 5. Gotchas & constraints (do not break these)

- **Build & deploy are Mac-only.** The Linux sandbox lacks the `@rollup/rollup-darwin-arm64` native binary. **NEVER run `npm install` in the sandbox** — it mutates the Mac's shared `node_modules` and broke the rollup binary once (Session 66). Run only read/verify/tsc/tests that don't reinstall platform deps.
- **The sandbox can create but NOT delete files under `.git`.** Stale `.git/index.lock` and `.git/refs/remotes/origin/main.lock` accumulate from any sandbox git command and block the next commit/push. Clear them on the Mac: `rm -f .git/index.lock .git/refs/remotes/origin/main.lock`. Do commits on the Mac; the sandbox can read/push.
- **Deploy targets are THREE and separate:** `npm run ship` = hosting + Android only. Cloud Functions + Firestore indexes need explicit `firebase deploy --only functions,firestore:indexes`. **Rules deploy separately** via `--only firestore:rules`. Functions have NO predeploy build hook — compile with `npm --prefix functions run build` before deploying them. Hosting predeploy runs the 270 tests (deploy aborts on failure — do not strip the predeploy hook).
- **Firestore rules can't be validated offline** — no emulator configured. Use the Firebase Console **Rules Playground** + version-history rollback as the safety net.
- **`.env` (gitignored, Mac-only) holds:** Metered TURN creds (`VITE_TURN_URLS/USERNAME/CREDENTIAL`), Firebase Web-Push VAPID key, Google Maps key. Vite bakes `import.meta.env.*` at BUILD time → any `.env` change requires a rebuild. Do not commit `.env`.
- **Android stale-bundle trap (happened 4×):** `firebase deploy` builds `dist/` but does NOT touch Android. Android ships only via `npm run cap:sync` / `npm run ship`, then **Run ▶**. Verify with `npm run android:check` before any device test.
- **Firestore hygiene:** no `undefined` fields (use explicit payload builders), null-guard every `.data()`, error callbacks on every `onSnapshot`. The only remaining `cp` file-sync is `pages/business.tsx ↔ pages/main/business.tsx`.
- **Encryption is a hard user constraint:** WebRTC media stays DTLS-SRTP encrypted; TURN relays ciphertext only; `turns:` (TLS) URL first. Don't weaken this.
- **Out of scope unless asked:** the DB migration (media base64→Firebase Storage, "D2") is TABLED by the user with no trigger; don't start it. Don't touch the just-stabilized messaging send/call path without the test suite + device testing.
- **When drafting anything the user sends as themselves:** tone is concise and direct, minimal formatting, no over-bolding.
